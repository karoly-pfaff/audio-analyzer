Supply decoded samples; decoding and playback belong to your application. Calls are synchronous. Use a worker for long recordings or whenever blocking the calling thread would interrupt your application.

Keep the units distinct. Signal measurements retain original amplitude. Musical feature channels are normalized to [0, 1]. Spectrum pixels are relative magnitudes. These values cannot be used interchangeably.

GET STARTED

Installation and imports

Install the package archive in your application:

npm install ./karoly-pfaff-audio-analyzer-0.1.0.tgz

The package uses ESM and includes TypeScript declarations. Supported Node.js versions are 24.18.1 through 24.x. For a browser application, import it through your ESM bundler. 

import { analyzeAudio, createAnalysisPcm } from '@karoly-pfaff/audio-analyzer';
import { analyzeSignal } from '@karoly-pfaff/audio-analyzer/signal';
import { analyzeSpectrum } from '@karoly-pfaff/audio-analyzer/spectrum';
import { estimateQuickTempo } from '@karoly-pfaff/audio-analyzer/tempo';

export { analyzeAudio, createAnalysisPcm, analyzeSignal, analyzeSpectrum, estimateQuickTempo };

Installing a published GitHub Packages version

GitHub Packages requires authentication even for public npm packages. Log in with a personal access token (classic) with read:packages, then install the exact released version. Credentials belong in your user-level npm configuration. 

npm login --scope=@karoly-pfaff --auth-type=legacy --registry=https://npm.pkg.github.com
npm config set @karoly-pfaff:registry=https://npm.pkg.github.com --location=project
npm install --save-exact @karoly-pfaff/audio-analyzer@0.1.0

A first measurement

import { analyzeSignal } from '@karoly-pfaff/audio-analyzer/signal';

export const summary = analyzeSignal({
  channels: [new Float32Array([0, 0.5, -0.5, 1.2])],
  sampleRate: 48_000,
});
// summary.channelCount === 1
// summary.frameCount === 4
// summary.peakAmplitude is approximately 1.2
// summary.clippedSampleCount === 1

Settings objects

Omitting a settings argument uses that API's defaults. When supplying settings, pass a complete object: spread the corresponding DEFAULT_* constant and override individual fields. Unknown fields and missing required fields are rejected. A schema's parse or safeParse method validates settings without running audio analysis.

EXAMPLES

Interactive examples

The examples generate PCM locally. Signal and spectrum use a 0.2-second sine; music uses a one-second sine; tempo uses 12 seconds of decaying pulses. Frequency changes the sine examples, pulse tempo changes the tempo example, and amplitude changes both. The invalid-PCM example shows the error returned for an empty channel list.
