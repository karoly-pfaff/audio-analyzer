MUSICAL ANALYSIS

Musical feature timelines

analyzeAudio(input, settings?, progress?) returns an AudioFeatureTimeline containing frame features, onsets, observed beats, sections and waveform peaks. Supply a mono analysis copy at exactly 22,050 Hz.

createAnalysisPcm(samples) validates and copies a nonempty finite Float32Array. If the sample peak exceeds one, it attenuates the copy to a peak of one; otherwise the gain is one. The returned inputPeak and normalizationGain describe that preparation. The function does not change the sample rate: passing 48 kHz samples does not resample them.

sourceSha256 and provenance.pcmSha256 must be lowercase, 64-character SHA-256 hex strings. The former identifies the source recording; the latter identifies the prepared PCM under your application's documented byte/channel policy. decoderVersion is a nonempty string of at most 1,000 characters describing the decoder and preparation used. Keep these values when saving a timeline.

Input and source-clock contract
Property Contract

Frame values and units

Field Interpretation
raw.rms Frame RMS amplitude of the prepared musical copy.
raw.sub / bass / mid / high Band power for 20–60, 60–250, 250–2,000 and 2,000–11,025 Hz respectively. Boundaries follow FFT-bin selection; values are not amplitudes or dB.
raw.centroidHz Frame spectral centroid in Hz.
raw.flatness A unitless [0, 1] descriptor of spectral flatness.

channels.beatPhase Null when no rhythm is accepted; otherwise an array of [0, 1] phase values and null gaps between unsupported beat intervals.

Read a value at a source time

Feature frame i corresponds to i / timeline.featureHz source seconds. Use the source clock when seeking. The valid interval is [0, durationSeconds); the exact endpoint is outside the timeline. 

import type { AudioFeatureTimeline } from '@karoly-pfaff/audio-analyzer';

export function readTimelineAt(timeline: AudioFeatureTimeline, seconds: number):
  { energy: number; beatPhase: number | null } | null {
  if (!Number.isFinite(seconds) || seconds < 0 || seconds >= timeline.durationSeconds) return null;
  const index = Math.floor(seconds * timeline.featureHz);
  const energy = timeline.channels.energy[index];
  if (energy === undefined) return null;
  return { energy, beatPhase: timeline.channels.beatPhase?.[index] ?? null };
}

Events, rhythm and sections

onsets contain id, time, strength and confidence; beats contain id, time and confidence. Times are source seconds. Event IDs belong to the source timeline and should be preserved when storing or presenting the result.

rhythm.bpm is null when rhythm is not accepted. Confidence and candidate scores are [0, 1] descriptors, not probabilities. ambiguous marks uncertainty between tempo interpretations. Each candidate supplies bpm, score, coverage, continuity and timing. The timeline can contain observed local beat intervals that do not match one fixed global BPM; use beat times for playback timing.

Sections cover the full source using contiguous [start, end) ranges. Their labels are sequential section names, not inferred verse/chorus labels. Energy, novelty and confidence are [0, 1]; optional tags are low-energy or high-energy. Changes have source time, confidence and kind build, drop, calm or shift. Novelty points include frame, source time, novelty and signed energy/trend deltas in [-1, 1].

waveform.minimum and waveform.maximum describe blocks of waveform.samplesPerPeak samples (1,024). Block i starts at i * samplesPerPeak / sampleRate seconds. The last block can be shorter. These peaks describe the prepared analysis copy; use /signal to measure original levels.

onsets.madMultiplier 2 0–10

Increase thresholdMultiplier or madMultiplier to require stronger onset evidence; minimumGapSeconds limits how closely accepted onsets may occur. Rhythm minimumConfidence controls acceptance, while the BPM bounds restrict candidate tempos. Section context and novelty thresholds affect where structural changes are detected. Reanalyze explicitly after changing settings. 

import { analyzeAudio, DEFAULT_ANALYSIS_SETTINGS } from '@karoly-pfaff/audio-analyzer';
import type { AnalysisInput, AnalysisProgress, AudioFeatureTimeline } from '@karoly-pfaff/audio-analyzer';

export function analyzeWithSettings(input: AnalysisInput, reportStage: (stage: AnalysisProgress) => void): AudioFeatureTimeline {
  const settings = {
    ...DEFAULT_ANALYSIS_SETTINGS,
    onsets: { ...DEFAULT_ANALYSIS_SETTINGS.onsets, thresholdMultiplier: 1.7 },
  };
  return analyzeAudio(input, settings, reportStage);
}

Progress callbacks occur synchronously in this order: features, onsets, rhythm, sections, validating. They report stages, not percentages or a cancellation mechanism. A callback exception propagates to the caller.

Using individual analysis functions

Use the same prepared PCM and source identity throughout a staged analysis:

import {
  extractFrameFeatures, detectOnsets, trackRhythm, analyzeSections,
  smoothFrameChannels, createOnsetEnvelope, createBeatPhase,
} from '@karoly-pfaff/audio-analyzer';
import type { AnalysisInput, FrameFeatures, OnsetEvent, RhythmResult, SectionAnalysis } from '@karoly-pfaff/audio-analyzer';

export function analyzeStages(input: AnalysisInput): {
  frames: FrameFeatures; onsets: readonly OnsetEvent[]; rhythm: RhythmResult;
  structure: SectionAnalysis; channels: FrameFeatures['channels'];
  onsetEnvelope: number[]; beatPhase: readonly (number | null)[] | null;
} {
  const frames = extractFrameFeatures(input.pcm, input.sourceSha256);
  const onsets = detectOnsets(frames);
  const rhythm = trackRhythm(frames, onsets);
  return {
    frames, onsets, rhythm, structure: analyzeSections(frames),
    channels: smoothFrameChannels(frames, onsets),
    onsetEnvelope: createOnsetEnvelope(frames, onsets),
    beatPhase: createBeatPhase(frames, rhythm),
  };
}

Stage outputs are separate observations; use analyzeAudio when you need a complete validated AudioFeatureTimeline. Keep onset IDs and frame clocks from the same source. hasObservedBeatInterval(beats, index) checks whether a beat pair has nearby interval support; a numeric BPM alone does not establish such an interval.

Custom envelope smoothing

import { smoothEnvelope } from '@karoly-pfaff/audio-analyzer';

export function smoothEnergy(values: readonly number[], featureHz: number): number[] {
  return smoothEnvelope(values, { featureHz, attackMs: 20, releaseMs: 200 });
}

Values must be finite and in [0, 1]. featureHz must be positive and at most 1,000; attackMs and releaseMs accept 0–10,000. Zero milliseconds follows the target immediately for that direction. The output has the input length; empty input yields an empty array. This smooths values on the supplied source clock and does not create beat events.
